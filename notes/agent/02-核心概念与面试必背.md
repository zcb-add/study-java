## 一、概念逐个讲透

### 1. Function Calling（函数调用）🟥
**一句话**：让大模型不只会"说"，还会"报工具名+参数"，由你（程序）去执行。
**完整流程（4 步，背下来）**：
1. **定义 schema**：告诉模型"我有这些工具，参数长这样"
2. **模型返回 tool_calls**：模型说"我要调 calculator，参数是 {'expression': '(1+2)*3'}"
3. **你执行工具**：把参数解析成 JSON，调用真的 Python 函数
4. **结果回填**：把工具结果作为 `role="tool"` 消息再发给模型，模型据此继续

```python
# 关键：模型返回的不是"命令"，而是"请求"——是否执行、怎么执行，是程序说了算
tool_calls = message.get("tool_calls")
if tool_calls:
    result = execute_tool_call(tc)          # 我们执行
    messages.append({"role": "tool", "content": json.dumps(result)})  # 回填
```

### 2. ReAct 循环（Reason + Act）🟥
**一句话**：让模型"想一步、做一步、看结果、再想"，直到完成，就像人解决问题。
**四步（背）**：
```
思考 Reason  → 行动 Act → 观察 Observe → 回答 Answer
```
**为什么不会死循环**：`MAX_TOOL_ROUNDS = 5`，超过就强制停止。

### 3. 工具注册表模式 🟥
**一句话**：工具和 Agent 核心解耦——加工具不改核心。
**面试话术**："我用了注册表模式，新增工具只需加一个模块并在注册表登记一行，Agent 循环代码零改动，高内聚低耦合。"

### 4. 双层记忆 🟥
- **短期记忆** = 当前对话上下文，存在 SQLite `messages` 表，发送前裁剪（保留最近 N 轮）
- **长期记忆** = 用户偏好，存在 `preferences` 表，会话开始时注入系统提示词
**为什么要分两层**：上下文窗口有限，全塞进去又贵又超限；而"用户住哪、叫什么"必须跨会话保留。

### 5. 为什么不能用 eval() 🟥
```python
# eval 能执行任意代码，等于给攻击者一个"执行权限"：
eval("__import__('os').system('del C:\\*.*')")
```
**解法**：`ast` 解析成语法树，只允许数字 + 四则运算节点，遇到函数调用/变量直接拒绝。
**面试话术**："计算器我没有用 eval，而是用 ast 白名单校验，从语法层面杜绝代码注入。"

### 6. 路径遍历攻击 🟥
**攻击**：模型被诱导写 `../../etc/passwd`，逃出沙箱目录。
**防护**：`.resolve()` 拿到绝对路径 → 检查是否仍在 `generated_files` 内 → 不在就拒绝。

### 7. SSE 流式输出 🟨
**一句话**：回答切成小块实时传，界面能逐字显示（打字效果）。
**格式**：每行 `data: {json}`，结束行 `data: [DONE]`。
**坑**：流式下工具参数是分片到达的，要按 `index` 拼接完整。

### 8. 生成器事件流（yield）🟨
**一句话**：Agent 用 `yield` 逐段吐事件（tool_call/tool_result/token/done），CLI 和 Streamlit 各自消费渲染。
**好处**：一套核心逻辑，两种界面，互不干扰。

### 9. SQLite 三张表 🟨
`preferences`（长期记忆）· `sessions`（会话）· `messages`（消息历史，外键挂 sessions，删除会话级联删除消息）。

## 三、面试自测题（先自己想，再翻笔记）

1. 大模型怎么"知道"该调用哪个工具？参数怎么传给它？
2. 工具执行结果怎么让模型"看见"？（答：role=tool 回填）
3. 如果模型连续调用 10 次工具还不回答，会怎样？项目里怎么防？
4. `eval("1+1")` 和 `eval(input())` 有什么风险？
5. "记住用户住乌鲁木齐" 存在哪张表？下次会话怎么让它生效？
6. 为什么加一个工具不用改 Agent 核心？
7. CLI 和网页版共用一套 Agent 逻辑，靠什么实现？
