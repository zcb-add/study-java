## 第 1 步 · 脚手架 + git init（chore: 初始化）

**做了什么**：建目录、`git init`、写 4 个基础文件。

```bash
mkdir -p agent-assistant/{agent,tools,storage,tests,generated_files}
cd agent-assistant
git init -b main          # -b main = 默认分支叫 main（GitHub 的规范）
```

**4 个基础文件**：
- `.gitignore` —— 哪些东西绝不进仓库（`.env` 密钥、`__pycache__`、数据库）
- `.env.example` —— API Key 的模板（复制成 `.env` 再填，密钥不进仓库）
- `requirements.txt` —— 依赖清单（requests / streamlit / python-dotenv / pytest）
- `config.py` —— 配置中心，所有常量集中一处

```python
# config.py 关键点
API_KEY = os.getenv("DEEPSEEK_API_KEY") or os.getenv("ANTHROPIC_API_KEY") or ""
```

> 🧠 为什么密钥放 `.env`？如果你把 key 写死在代码里再推 GitHub，等于把密码公之于众——爬虫几分钟就能扫到你的 key 拿去烧钱。**`.env` + `.gitignore` 双保险。**

**验证**：`git status` 干净，第一次 commit 成功。

## 第 2 步 · 存储层：SQLite（feat: SQLite 存储）

**做了什么**：3 张表 + 3 个模块。

```sql
preferences  表 —— 长期记忆：key, value（用户偏好）
sessions     表 —— 多会话：id, title, 时间
messages     表 —— 每个会话的消息历史（短期记忆的载体）
```

**为什么每张表都要**：
- `preferences` → "记住用户偏好"，跨会话有效
- `sessions` + `messages` → Streamlit 里能**新建/切换/删除会话**，重启程序记录还在

**设计细节**：`db.py` 只暴露 3 个函数 `execute / fetch_all / fetch_one`，上层不用碰 sqlite3 细节。每次操作**用完即关**（SQLite 连接不能跨线程共享，Streamlit 每次交互在不同线程）。

> 🧠 什么是"持久化"？程序关掉，数据还在磁盘上。SQLite 就是一个小型数据库，数据存在一个 `.db` 文件里，零安装、Python 自带。

**验证**：存偏好 → 读出来 → 建会话 → 存消息 → 删会话，全通。

## 第 3 步 · 工具层：10 个工具 + 注册表（feat: 注册 10 个工具）

**做了什么**：6 个工具模块，每个暴露一个 `TOOLS` 字典（名字 → schema + 函数）。

```
file_tools.py     create_text_file / read_text_file / list_files
compute_tools.py  calculator（安全版）/ get_current_time
web_tools.py      web_search / fetch_url
weather_tools.py  get_weather
memory_tools.py   remember_user_preference / recall_user_preferences
```

**注册表模式**（`tools/__init__.py`）—— 本项目最值钱的工程模式：

```python
_MODULES = [file_tools, compute_tools, web_tools, weather_tools, memory_tools]

# 汇总：{工具名: 执行函数}
REGISTRY = {}
for mod in _MODULES:
    REGISTRY.update({name: t["func"] for name, t in mod.TOOLS.items()})

def build_tools():        # 返回所有工具的 schema（发给模型）
def execute_tool_call():  # 解析模型的 tool_call → 分发到对应函数
```

> 🧠 加一个新工具，只需要：写一个新模块（定义 schema + 函数）→ 在 `_MODULES` 加一行。**Agent 核心一行都不用改**。这就是"低耦合"。

**两个安全亮点**（面试必问）：

```python
# 1. 计算器为什么不用 eval()？
# eval("__import__('os').system('rm -rf /')") 能执行任意代码！
# 改用 ast 解析，只允许数字和四则运算节点：
if isinstance(node, ast.Constant) and isinstance(node.value, (int, float)):
    return node.value
# 遇到变量、函数调用直接抛错 → 恶意代码执行不了

# 2. 路径安全（防止路径遍历攻击）
# 用户让模型写 ../../etc/passwd → 用 .resolve() 解析后
# 检查是否还在 generated_files 目录内，不在就拒绝
if target != base_dir and base_dir not in target.parents:
    raise ValueError("路径越界")
```

**验证**：`(1+2)*3**2 = 27` ✅；`__import__('os')...` 被拒 ✅；`../../evil.txt` 被拦 ✅。

## 第 4 步 · Agent 核心：ReAct 循环 + 流式（feat: Agent 核心）

**做了什么**：4 个模块，其中 `core.py` 是灵魂。

```
agent/llm.py          调模型：非流式 + SSE 流式
agent/core.py         ★ ReAct 循环（生成器事件流）
agent/messages.py     短期记忆裁剪
agent/system_prompt.py 系统提示词 + 长期记忆注入
```

**ReAct 四步**（`core.py` 主循环）：

```
思考 Reason   ：把上下文发给模型，问它"直接答，还是调工具？"
行动 Act      ：模型说"调 calculator"，我们执行
观察 Observe  ：把工具结果回填给模型，让它继续
回答 Answer   ：模型不再调工具，输出最终答案
```

**生成器事件流设计**（本项目第二个工程亮点）：

```python
def stream_chat(self, messages):
    ...
    yield {"type": "tool_call", "name": "get_weather", "args": {...}}   # 界面显示"正在调工具"
    yield {"type": "tool_result", "ok": True, "summary": "..."}          # 界面显示结果
    yield {"type": "token", "content": "北京的天气..."}                   # 最终答案逐字流出
    yield {"type": "done", "answer": "..."}                              # 完成
```

> 🧠 为什么用 `yield` 而不是普通 return？CLI 和 Streamlit 两种界面都要消费这个过程：CLI 打印、Streamlit 渲染成"工具卡片+流式打字"。生成器让**一套逻辑服务两种界面**。

**SSE 流式**（`llm.py`）：把回答切成小块实时传，而不是一次性全给。
关键格式：每行 `data: {json}`，结束行 `data: [DONE]`。工具参数是分片到达的，要按 `index` 拼起来。

**双层记忆注入**（`system_prompt.py`）：
```python
prefs = format_preferences_for_prompt()   # 从数据库读用户偏好
if prefs:
    return BASE_PROMPT + "\n\n## 关于当前用户\n" + prefs   # 注入系统提示词
```
会话一开始，模型就知道"这个用户是小阳，住乌鲁木齐"。

**验证**（真实调 API）：输入"算 27 并存文件" → 模型**自主连调 2 个工具** → 给出总结回答。✅
